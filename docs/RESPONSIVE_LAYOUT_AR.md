# العرض المتجاوب للموقع

تتكيف صفحات المشروع الحالية مع الشاشات الصغيرة عبر ملف واحد: [responsive.css](../frontend/src/styles/responsive.css). تحتفظ المكونات بالتنسيق الأصلي، وتضيف قواعد العرض المتجاوب عند المقاسات المحددة. تستخدم خصائص `data-page` لتحديد الصفحة و`data-responsive` لتحديد أجزاء العرض، دون تعديل طلبات API أو احتساب النتائج أو منطق الألعاب.

## المقاسات

| عرض الشاشة بوحدة CSS pixels | العرض |
| --- | --- |
| 1200 فأكثر | التصميم الأصلي للشاشات الواسعة وفوتر الأنشطة الأصلي |
| حتى 1199 | قائمة أنشطة جانبية، هيدر مرن، جداول قابلة للتمرير الداخلي، وتمرير صفحات الأنشطة |
| حتى 767 | هيدر على صفين عند الحاجة، تكديس المحتوى، وتكييف حقول الدخول ولوحة الرسم وتقرير الطالب |
| حتى 479 | ضبط إضافي للعناوين ومقدمة الطالب ولوحة الحروف |
| شاشة ضيقة بارتفاع حتى 500 | تكييف إضافي للألعاب في الوضع الأفقي |

تعتمد الحدود على مساحة المحتوى المتاحة وليس على اسم الجهاز. لابتوب ضيق قد يستخدم نفس تنقل التابلت بدلاً من ضغط ست بطاقات فوتر في مساحة غير كافية.

## ما تغير في العرض؟

- الدخول واختيار الحساب: بطاقات مرنة، تدفق رأسي على الهاتف، وإبعاد الرسوم الزخرفية التي تزاحم النموذج.
- صفحات الطالب والحروف: السماح بتمرير الصفحة بدلاً من قص المحتوى عند ارتفاع الشاشة، وتقليل أعمدة لوحة الحروف حسب العرض.
- تعلم الحرف والكتابة والمكان والتشكيل والفيديو والألعاب: مسافات وأحجام مناسبة، ولوحة رسم لها مساحة فعلية على الهاتف، وعناوين وبطاقات تتكيف مع العرض.
- صفحات المعلم والمكتبات والصفوف: هيدر مرن، بطاقات تتكيف مع العرض، وتمرير الجداول داخل منطقتها مع الاحتفاظ بالأعمدة والأزرار.
- تقرير الطالب: ترتيب إحصاءات الطالب فوق تفاصيل الأنشطة في الهاتف، ومساحات داخلية مرنة للنشاطات والحروف المدروسة.
- الألعاب: حجم شبكة الذاكرة ومساحات اللعب يتكيفان مع الشاشة، مع إبقاء الترتيب والأحداث والمؤقتات والنتائج كما هي.
- النوافذ: إتاحة التمرير الداخلي للشاشات القصيرة، وتكييف نموذج إنشاء الصف، والمحافظة على إتاحة زر إغلاق الفيديو.

## قائمة الأنشطة

يظل الفوتر الأصلي للشاشات الواسعة. على المقاسات الأصغر يظهر زر «الأنشطة» مع أيقونة همبرغر، ويفتح قائمة من اليمين بنفس الصور والمسارات الأصلية. تغلق القائمة بزر الإغلاق أو الخلفية أو Escape أو اختيار نشاط، وكذلك عند الانتقال إلى عرض الديسكتوب. يُحصر تنقل Tab داخلها أثناء الفتح، ويُمنع تمرير الخلفية، ثم يعاد التركيز إلى زر الفتح عند الإغلاق.

القائمة فقط تضيف حالة فتح وإغلاق وأحداثاً خاصة بالتنقل وإمكانية الوصول؛ لا تضيف عمليات حفظ أو تغييراً في بيانات الطالب.

## التحقق وحدوده

- نجح بناء الإنتاج باستخدام `npm.cmd run build`.
- نجحت اختبارات طبقة API الموجودة.
- قورنت مكونات الصفحات مع نسختها قبل التعديل: بقيت الشروط والدوال والأحداث والنصوص والستايلات الأصلية كما هي؛ الإضافات فيها خصائص لتوجيه CSS. يستثنى من ذلك `ActivityFooter` الذي أضيفت له القائمة والتفاعل اللازم لها، و`main.tsx` الذي يستورد ملف CSS الجديد.
- جرى فحص إنشاء HTML لتنقل الأنشطة باستخدام React Server Rendering: ظهرت الوجهات الست الأصلية وزر فتح القائمة، وكانت القائمة مغلقة افتراضياً.
- نجح فحص إنشاء HTML لـ19 صفحة وحالة عرض باستخدام React Server Rendering وبيانات حساب افتراضية محلية، دون تنفيذ Effects أو إرسال طلبات إلى الخادم. يشمل ذلك حالات التحميل والفراغ؛ ليس بديلاً عن اختبار صفحات البيانات المحملة داخل المتصفح.
- لم يتاح فحص بصري تفاعلي: اتصال المتصفح غير متاح، وانتهت مهلة طلب الوصول إلى نافذة Edge. لذلك لا تعد هذه الفحوص إثباتاً بصرياً لكل مقاس أو لكل شاشة محملة ببيانات فعلية.

قبل الاعتماد النهائي، تُراجع الصفحات بصرياً بعروض 320 و375 و430 و768 و1024 و1366، وبالوضع الأفقي، مع التركيز على: ظهور أزرار الحفظ والخروج والإغلاق، عدم خروج محتوى الصفحة أفقياً، التمرير داخل الجداول، رسم الحرف باللمس، سحب بطاقات التصنيف، فتح القائمة وإغلاقها بلوحة المفاتيح، وفصل تقدم الحروف كما في السابق. هذه مصفوفة مراجعة مطلوبة وليست نتائج اختبارات بصرية منفذة.
